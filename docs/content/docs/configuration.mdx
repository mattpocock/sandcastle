## Config Directory

The `.sandcastle/` directory in your repository contains all Sandcastle configuration:

- `main.mts` -- Your orchestration script (calls `run()` / `runMany()`)
- `Dockerfile` -- Defines the sandbox environment
- `prompt.md` -- The prompt sent to the agent on each invocation
- `.env` / `.env.example` -- Environment variables for the sandbox

## Run options

Run behaviour is configured in code, on the call in `main.mts` — there is no config file. Sandcastle has two entry points:

- `run()` invokes the agent **once**. Use it for one-shot tasks and for [structured output](https://github.com/mattpocock/sandcastle#structured-output).
- `runMany()` invokes the agent in a **loop**, stopping when the agent emits the completion signal (`<promise>COMPLETE</promise>` by default) or after `maxIterations`.

```ts
import { runMany, claudeCode } from "@ai-hero/sandcastle";
import { docker } from "@ai-hero/sandcastle/sandboxes/docker";

await runMany({
  agent: claudeCode("claude-opus-4-8"),
  sandbox: docker(),
  promptFile: "./.sandcastle/prompt.md",
  maxIterations: 10,
});
```

| Option             | Applies to  | Description                       | Default                         |
| ------------------ | ----------- | --------------------------------- | ------------------------------- |
| `agent`            | both        | The agent provider to use         | —                               |
| `maxIterations`    | `runMany()` | Maximum iterations per run        | `1`                             |
| `completionSignal` | `runMany()` | String(s) that end the loop early | `"<promise>COMPLETE</promise>"` |
| `output`           | `run()`     | Structured output definition      | —                               |

## Prompt

The `prompt.md` file is the instruction text passed to the agent at the start of each invocation (each iteration, for `runMany()`). It supports:

- **Prompt arguments** -- `{{KEY}}` placeholders replaced with values from `promptArgs`
- **Shell expressions** -- `` !`command` `` markers that evaluate shell commands inside the sandbox

## Environment Variables

Sandcastle resolves environment variables from multiple sources in order:

1. Repository root `.env`
2. Config directory `.env`
3. `process.env`

Only keys declared in a `.env` file are resolved from `process.env`.
