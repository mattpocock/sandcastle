v1: `bwrap()`, a Bubblewrap provider for Linux and WSL2 at `@ai-hero/sandcastle/v1/sandboxes/bwrap`, a drop-in for the remote providers. Nothing of the caller's is mounted: each sandbox starts with an empty working directory (`/home/agent/workspace`) to clone into, and sees only the host's system folders and the folders that hold its `node`, `git`, `gh` and agent CLIs, read-only. `bwrap({ create: { network?, toolchainPaths? } })` (`BwrapCreateOptions`) shares the host network by default, or none with `network: "none"`, and shows extra toolchain folders read-only. Each sandbox is a folder under `$XDG_STATE_HOME/sandcastle/sandboxes/`, owned by a keeper process started in its own session: every command runs under it, and at the kill time, or on `close()`, it kills them all and removes the folder. So its sandboxes are detachable: detached work outlives the caller's process (not a reboot), and `reattachSandbox` and `status()` work as on `daytona()`. Env reaches each command through its environment, never its command line. `createSandbox` fails with 0.x's preflight message when Bubblewrap can't run, and names any of `node`, `git` and `gh` the host is missing. See `docs/v1/bwrap.md`.
