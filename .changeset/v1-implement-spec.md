v1 (`@ai-hero/sandcastle/v1/tasks`): `implementSpec`, a bundled task that builds a whole spec's tickets onto one integration branch, in rounds on one sandbox. It's written only against the public API (the handle, a chooser, `implement`, `merge` and `exec`). `implementSpec.start(sandbox, { repo, spec, githubToken, skillsContext, setup?, record?, agent?, maxConcurrent?, chooser? })` creates and pushes `sandcastle/implement-spec-<spec>-<random>` from the default branch, runs the chooser (default `sessionChooser()`), and spawns one `implement` session named `implement-<ticket>` per chosen ticket, at most `maxConcurrent` (3), each on a new branch from the integration branch. `implementSpec.next(sandbox, { input, state, report })` reads the round's finish report: each opened or updated PR gets a `merge` session named `merge-<ticket>` into the integration branch, one per round; `no-changes` counts as merged; a `blocked` ticket, a failed merge or a failed session leaves the ticket stuck, and tickets it blocks are skipped; a session stopped by the detach deadline is retried once as `<step>-<ticket>-retry`. With no merge waiting it runs the chooser again and spawns the next round, or resolves `done` with an `ImplementSpecResult` (`complete`, `partial` or `blocked`, with the tickets merged, stuck and skipped). `implementSpec.outputs(state)` gives the round's `Output` definitions for `verifyFinishReport`, and `implementSpec.run(sandbox, input)` runs every round on a held handle. `state` is plain JSON with no token. `implementSpec.limits` is `{ timeLimitMinutes: 480, deadlineMinutes: 90 }`; `start` and `next` reject before spawning anything when the kill time leaves less than a round. Nothing is ever merged into the default branch.
